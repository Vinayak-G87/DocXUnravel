# Security policy

## Reporting a vulnerability

Please **do not** report vulnerabilities in public GitHub issues, pull requests, discussions or social media, and do not publish exploit details before a fix is coordinated. Use this repository's **Security → Report a vulnerability** private reporting form. Maintainers should enable GitHub private vulnerability reporting before a public release; if the form is unavailable, contact the repository owner privately via their GitHub profile contact details and ask for a secure reporting channel without including exploit details in public messages. Do not send sensitive documents, credentials or tokens with an initial report.

Include the affected version, reproduction steps or a minimal synthetic DOCX, expected and observed behavior, and potential impact. Maintainers should acknowledge privately, investigate, coordinate a fix and disclosure timing with the reporter, and publish an advisory when appropriate. Please allow time for a fix before public disclosure; no response-time guarantee is currently offered.

## Supported versions

Security fixes are intended for the latest published release; older versions may need to upgrade. Until the first PyPI release, report issues against the current repository code using the same private channel. This policy does not imply that private reporting or any release automation is already configured.
